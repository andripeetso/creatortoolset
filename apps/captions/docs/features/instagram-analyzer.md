# Instagram Analyzer on a phone

### Instagram Analyzer on a phone (`MobileInstagramPage`)

Paste or share links in, and look through everything in the Analyzer. `MobileAnalyzerLibrary` lists all posts with search and Content / Format / Know-how chips (`onShelf` in `src/lib/instagram.ts`). A post opens full screen with `SlideViewer`, its numbers, idea, caption and a link to Instagram. The iPhone app's Analyzer tab is this page.

Each post says how it is doing (`postHealth`): crawling, stuck (processing, nothing written for 15 minutes), failed, part failed (a job errored), or not crawled yet (saved for later: status "ready" with jobs still pending). Those get Run or Retry (`POST /:id/retry`), plus "Needs a run" and "Run them all" at the top. A refused run shows the server's reason (for example, no Instagram connection).

## YouTube videos and Shorts

Paste a YouTube link (youtube.com/watch?v=, m.youtube.com, youtu.be/, /shorts/, /live/) in the Analyzer's add box, the phone's share sheet or the Workshop's paste box. It becomes a library post with its words.

- **Where it lives.** A post with `platform: "youtube"` (absent = Instagram, so old posts are unchanged). `shortcode` is `yt-<videoId>`, so it never clashes with an Instagram shortcode. A Short is kind `reel`; a long video is kind `post`. The badge says YouTube and the link says "Open on YouTube". The channel is the creator (`username` = its @handle, else the channel name). It is never filed as an Analyzer account, and it is left out of the Workshop's "own posts" list.
- **Info comes from Apify only**: `streamers~youtube-scraper` (`api/lib/youtube/fetch.ts`), one run per link, on the user's own Apify token. The server has no yt-dlp, and YouTube blocks datacenter IPs, so there is no download path. Input: `startUrls`, `maxResults: 1`, `maxResultsShorts: 1`, `maxResultStreams: 0`, the subtitle options (`subtitlesLanguage: "en"`, `subtitlesFormat: "srt"`, `preferAutoGeneratedSubtitles: true`).
- **Output used**: `id`, `title`, `text` (description), `thumbnailUrl`, `viewCount`, `likes`, `commentsCount`, `date`, `duration`, `channelName`, `channelUrl`, `subtitles[]`. An item with `error` (for example `VIDEO_UNAVAILABLE`) fails the post with its `note`.
- **Mapping.** Caption = title, a blank line, the description. Views go in `plays` (the Analyzer sorts by plays), with likes and comments. The thumbnail is the one slide (`media/00.jpg`), so the post has a picture and the Workshop pack has it.
- **Transcript.** YouTube's own captions (SRT) become timed words, each cue's words spread over its span; rolling auto-caption repeats are dropped. They are stored as `transcripts/00.json`. With no captions, the transcript job says so in the post's warnings and is skipped.
- **Not done.** Comments and reading the video's own frames. No media download.

**Untested until a live run** (no Apify token in the test environment): the actor's value for free subtitles, whether `subtitles[].srt` comes back inline or only as `srtUrl`, and the `date` format. The normaliser is tested against a fixture shaped like the documented output (`api/lib/youtube/normalize.test.ts`).
