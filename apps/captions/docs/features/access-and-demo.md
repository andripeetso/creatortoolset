# Access, demo and guests

- **Access is per app.** Admin → Access is a grid: a row per account, a column per app, in the home page's order. A tick saves at once and is stored as `off` in users.json. Admins always have every app. New accounts get every app.
- **Roles** say who is an admin and how long uploaded files are kept: admin files are kept; team files go after 28 days; user files after 14 (see `api/retention.ts`). Client: `canUse(me, tool)` in `src/lib/auth.ts`. Server: `TOOL_GATES` in `api/boot.ts` for the apps that read each other's APIs; the others are only hidden, and their data is the user's own.
- **Guests** (no account) get Caption Studio and Story Splitter. Cloud transcription and the AI pass run on the API key only when an admin switches that on for guests (Settings → Admin → AI access). Guests are capped in `api/guest.ts` (video length and daily budgets), their runs are listed in Admin → Guests, and their Review uploads are kept 7 days (`GUEST_KEEP_DAYS`).
- **Demo.** The login screen shows a "Demo" button once an account called `demo` exists (`DEMO_USER`). A visitor gets a `demo-<id>` cookie for a day. It reads the demo account as a plain user, never as an admin, and every other change is refused with 403 and `X-Demo` (`boot.ts`). In the browser such a change never leaves the page, so nothing is saved and nothing is said. The demo's apps are fixed in code (`DEMO_OFF` in `auth.ts`: everything except Video Notes and Guide Builder).
- **Demo Review.** A visitor's Review copy is made from the demo's own videos (`cloneDemoReview`). The visitor can comment, draw, pin and approve in it, but cannot upload. Retention removes a visitor's copy after a day and never the demo's own. New visitors are limited per hour.
